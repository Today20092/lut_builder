Camera thresholds and sources

Match the whole profile. Camera brand alone is insufficient: log curve, gamut, and the documented input-range convention must agree with the source. Threshold evidence is specific to each profile.

Each floor is the curve’s encoded zero-light level. Each ceiling is where that camera family’s recorded signal stops, from the manufacturer where one is published and otherwise from a labelled measurement. None is a per-body sensor calibration. Match the log curve and gamut together. The values are maintained in the browser catalog and Python catalog.

Reading the examples

Section titled “Reading the examples”

All examples below use a 65³ cube, both warnings enabled, and normalized camera RGB at exact lattice nodes. Each comparison includes t = 0.015625, one grid step. They illustrate the exported warning rule, not sensor performance or an arbitrary interpolated pixel. Warning colors override exposure bands; high wins when both trigger.

The camera documents linked below support curve/gamut interpretation. A source link in the catalog does not by itself prove every warning constant. Where the repository has no reproducible derivation, that gap is stated rather than assigning a false precision or a camera-wide guarantee.

Sony S-Log3

Section titled “Sony S-Log3”

Input: S-Log3 with S-Gamut3.Cine. The cited Sony specification defines normalized S-Log3 as 10-bit code divided by 1023. Do not substitute S-Gamut3 or an already display-converted signal.

Evidence: Sony’s S-Log3/S-Gamut3 technical summary, appendix gives the zero-light code as 95. 95 / 1023 = 0.092864125…, consistent with the catalog’s rounded 0.0929 floor. Sony support documentation states that S-Log3’s maximum is 94% in video output. On the 10-bit legal scale that is 64 + 0.94 × 876 ≈ 887, and 887 / 1023 ≈ 0.867 in the full-range code values Sony records, so the 0.867 ceiling marks where Sony cameras stop. Earlier releases used 0.94 (code 962, about 102% video), which S-Log3 cameras do not reach, so clipped highlights were not flagged. The value is still not a per-camera sensor measurement.

Worked example: low is min(R,G,B) <= 0.108525; high is max(R,G,B) >= 0.851375. (0.09375, 0.5, 0.5) triggers low. (0.859375, 0.5, 0.5) triggers high; (0.84375, 0.5, 0.5) does not. Sony’s 18% reference is code 420, or about 0.41056; that encoded value is not 41% scene-linear light.

Limit: the 94% maximum is Sony’s family-wide statement. Lower ISOs or bodies with less highlight range can stop slightly earlier; a7S III footage measures about 0.871, just above the ceiling.

Panasonic V-Log

Section titled “Panasonic V-Log”

Input: V-Log with V-Gamut, full-range code divided by 1023.

Evidence: Panasonic’s V-Log/V-Gamut reference manual lists black at code 128 (128 / 1023 = 0.12512, the 0.1251 floor) and VariCam 35 clipping at code 911. 911 / 1023 = 0.89052, so the ceiling is 0.8905. It was previously 0.8906, a rounding just above code 911. S5II/S5IIX measurements also report code 911 (Gamut).

Worked example: low is min <= 0.140725; high is max >= 0.874875. (0.140625, 0.5, 0.5) triggers low; (0.875, 0.5, 0.5) triggers high; (0.859375, 0.5, 0.5) does not.

Limit: GH-series V-Log clips lower (reported codes 762–837 depending on Dynamic Range Boost), so this ceiling will not flag GH6/GH7 clipping.

Canon Log 3

Section titled “Canon Log 3”

Input: Canon Log 3 with Cinema Gamut. Canon’s v1.2 constants are legal-range values applied to code divided by 1023.

Evidence: Canon Log 3’s zero-light output is code 128 (0.12512), the 0.1251 floor. Earlier releases used 0.04, which is below black and could not trigger. Canon publishes no clip code. Its C300 Mark II white paper places sensor saturation near +6.3 stops, about code 1017. C70 and C300 Mark III users report clipping at 85–90 IRE. The ceiling uses 85 IRE (code 809, 0.79). The previous 0.90 was about 98 IRE, which those cameras do not reach.

Worked example: low is min <= 0.140725; high is max >= 0.774375. (0.140625, 0.5, 0.5) triggers low; (0.78125, 0.5, 0.5) triggers high; (0.765625, 0.5, 0.5) does not.

Limit: unverified. A C300 Mark II will warn about two stops early. Measure your body’s clip on a waveform before relying on it.

ARRI LogC3

Section titled “ARRI LogC3”

Input: ARRI LogC3 with ARRI Wide Gamut 3, full-range code divided by 1023, decoded at EI 800.

Evidence: ARRI’s Log C usage document defines black as sensor code 256/65535 and the maximum as full sensor signal. Through the EI 800 parameters those encode to code 95 (0.0928 floor) and code 976. ARRI’s false-color specification starts red at code 951, one-third stop below clipping. That is the 0.9296 ceiling. The previous 0.03 floor was below black and could not trigger.

Worked example: low is min <= 0.108425; high is max >= 0.913975. (0.09375, 0.5, 0.5) triggers low; (0.921875, 0.5, 0.5) triggers high; (0.90625, 0.5, 0.5) does not.

Limit: EI-specific. At EI 400 the sensor clips at code 917, below this ceiling, and at EI 1600 it reaches code 1023.

RED Log3G10

Section titled “RED Log3G10”

Input: Log3G10 with REDWideGamutRGB, full-range code divided by 1023. The builder does not read R3D RAW.

Evidence: RED’s Log3G10 white paper encodes linear zero at 0.091551 (0.0916 floor) and reaches 1.0 only at +10 stops. The previous 0 and 1 thresholds could therefore never trigger. RED publishes no clip code. KOMODO at ISO 800 measures code 817 (Gamut), the 0.7986 ceiling.

Worked example: low is min <= 0.107225; high is max >= 0.782975. (0.09375, 0.5, 0.5) triggers low; (0.796875, 0.5, 0.5) triggers high; (0.78125, 0.5, 0.5) does not.

Limit: unverified, and the clip code moves with ISO and body. The camera’s own exposure tools see the sensor directly and remain authoritative.

Blackmagic Film Gen 5

Section titled “Blackmagic Film Gen 5”

Input: Blackmagic Film Generation 5 with Blackmagic Wide Gamut, after video-level expansion: 10-bit codes 64–940 map to 0–1. Code 145 becomes (145 − 64) / 876 = 0.0924657534….

Evidence: the existing Blackmagic research traces the floor to the constant E in encoded = D × linear + E: linear zero is 0.09246575342465753. Blackmagic publishes no clip code. Pocket 4K/6K at ISO 400 measure code 814 (Gamut), or (814 − 64) / 876 = 0.8561 in this domain. The previous ceiling of 1 (code 940) could not trigger.

Worked example: low is min <= 0.10809075342465753; high is max >= 0.840475. (0.09375, 0.5, 0.5) triggers low; (0.84375, 0.5, 0.5) triggers high; (0.828125, 0.5, 0.5) does not.

Limit: unverified. The same source also lists code 850, and the clip moves with ISO. BRAW decode settings and highlight recovery change the samples.

Evidence status

Section titled “Evidence status”

Source check: November 10, 2026. Sony and Panasonic documents were retrieved directly. Unavailable vendor links above remain as the catalog’s original references, with their access and derivation limits explicit. Review the repository’s profile contribution requirements before proposing a threshold correction. Missing evidence is a reason to investigate; it is not permission to silently change LUT behavior.
